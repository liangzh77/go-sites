Paseo 中文使用指南 · 非官方笔记

把电脑上的 AI Agent，
装进口袋。

电脑负责运行，手机负责指挥。通过 Paseo 和 Tailscale，随时调用电脑上的 Codex、pi 和不同模型，继续你的开发任务。

  • 手机遥控
  • 电脑执行
  • 多 Agent
  • 多模型
开始连接 → 看懂原理

本指南基于一台 Mac 的真实配置写成，其他平台请以官方文档为准。本机 Paseo 版本 0.11.4（2026-10-18 核对）。

第 01 章 · 原理

手机指挥，电脑执行

整条链路只有四个角色：手机上的 Paseo App、Tailscale 私网、电脑上的 Paseo，以及电脑里真正干活的 Agent 与模型。

手机Paseo App → Tailscale 私网跨网络连接 → 电脑Paseo

路径一 · Codex

Codex Agent → Codex 模型

路径二 · pi

pi Agent → 多种模型
DeepSeekCodex 模型Kimi K3
Paseo统一入口
把手机和电脑上的 Agent 连起来的工作台：在手机上看到项目、发起任务、查看进展。
Tailscale跨网络私网
让手机和电脑无论身在哪个网络，都像在同一个私有局域网里一样通信。
Codex / piAgent
真正干活的角色：读文件、改代码、运行命令。
模型思考与生成
负责思考和生成的角色：DeepSeek、Codex 模型、Kimi K3 等，由 Agent 调用。
关键理解

不是手机在运行开发环境，而是手机在使用电脑上的环境。

文件与命令执行留在电脑上；模型推理由所选供应商提供，手机负责查看与指挥。

第 02 章 · 安装（Mac 实例）

先把电脑这一端装好

四步：装 Paseo 桌面版、装 Codex CLI、装 pi、回 Paseo 确认。全部在电脑上完成。

  1. 1

    下载安装 Paseo 桌面版

    桌面版自带 daemon，安装后自动启动，不需要再单独安装一个 daemon。

    官方下载 paseo.sh/download ↗

  2. 2

    安装 Codex CLI 并登录

    先在终端验证它能正常工作，再回到 Paseo。

    展开安装命令 
    npm install -g @openai/codex
# 然后运行并登录，确认可用
codex

    Codex CLI 官方文档 ↗

  3. 3

    安装 pi

    需要 Node.js 22.19 或更高版本。安装后在 pi 内用 /login 配置供应商，用 /model 选择模型。

    展开安装命令 
    npm install -g --ignore-scripts @earendil-works/pi-coding-agent
pi

    pi 官网 pi.dev ↗

    两套 Agent 的凭据分别配置：不要复制、不要共用会刷新的 OAuth token 文件；API key 只留在电脑上，不写进任何网页。
  4. 4

    在 Paseo 里确认一切就绪

    确认 Codex 和 pi 都显示可用；选择一个项目，先在电脑上完成一条简单的只读任务，熟悉流程。菜单名称以你的版本为准。

第 03 章 · 连接（重点）

让手机连上电脑，照着做

六步可跟做。页面里只出现示例地址，不含任何真实设备名、IP、账号或二维码。

  1. 1

    两端都装上 Tailscale

    手机和电脑都安装 Tailscale ↗，登录同一个账号（同一个 tailnet），确认两端都显示已连接。手机也需从 Paseo 官方下载页 ↗ 安装对应客户端。

  2. 2

    拿到电脑的私网 IP

    在电脑终端执行 tailscale ip -4，记下输出——那是电脑在私网里的地址。

  3. 3

    修改 Paseo 的监听配置

    先备份，再编辑 ~/.paseo/config.json：只合并必要字段，保留原有 daemon、agentProfiles、auth 等设置。

    展开配置片段（合并用，勿整份覆盖） 
    {
  "daemon": {
    "listen": "100.101.102.103:6767",
    "relay": { "enabled": false }
  }
}

    100.101.102.103 仅是示例，必须换成第 2 步里自己电脑的 IP。这段 JSON 是合并片段，不能整份覆盖你的配置。这里复现的是本机的 Tailscale 直连方案；关闭 Paseo relay 不代表禁止 Tailscale 自己的中继机制。

  4. 4

    重启 daemon 使监听生效

    listen 是启动参数，改完要重启才生效。等正在运行的任务结束，到桌面版 Settings → your host → Overview → Restart daemon。

    重启会中断正在运行的 Agent，不要在任务进行中执行。命令行用户也可以用 paseo daemon restart（桌面版不一定在 PATH 上提供 CLI）。
  5. 5

    手机添加主机（Direct connection）

    手机保持 Tailscale 已连接，打开 Paseo → Settings → Add host → Direct connection：

    Host
    自己电脑的 Tailscale IP
    Port
    6767
    Use SSL
    本示例关闭（私网直连，加密已由 Tailscale 提供）
    密码
    如果你给 daemon 配置了密码，在这里填写

    不需要点 Enable relay——relay 扫码是另一条路径。也不用开放任何公网端口。

  6. 6

    发一条只读任务验证链路

    选择这台电脑和一个项目，发送：

    请列出当前项目的顶层目录，不要修改任何文件。

    能收到符合预期的只读回复，链路就通了。

前提与提醒

电脑开机、联网、Paseo 正常运行，是一切的前提。Tailscale 的 ACL 与设备安全依然重要；建议启用 Paseo daemon 密码 ↗。官方连接步骤见 Connectivity 文档 ↗。

第 04 章 · 选择

两条路径，各取所需

同样从 Paseo 出发，可以走进 Codex 的原生世界，也可以走进 pi 的多模型世界。

路径一

Paseo → Codex

保留 Codex 原生 Agent 的工作方式，把 Codex 的使用入口延伸到手机。

Paseo→Codex Agent→Codex 模型
路径二

Paseo → pi → Codex 模型

用相同的模型系列，体验 pi 简洁、可扩展的 Agent；也可以切换到不同供应商的模型。

Paseo→pi Agent→多种模型
一句话记住

使用 Codex 模型，不等于使用 Codex Agent。

模型可以相同，驱动它的 Agent 不同——权限、工具、会话行为都随 Agent 而异。两条路径不共享会话。

第 05 章 · 分工

给每个角色派合适的活

以下是作者的个人使用经验，按任务顺手程度排列，不是客观排行榜。

  • 办事员

    DeepSeek + pi

    日常问答、文字整理、简单任务。

  • 程序员

    Codex 模型 + pi

    编程、复杂分析，搭配 pi 简洁的工作方式。

  • 前端

    Kimi K3 + pi

    UI 设计、页面布局、视觉表现——我做 UI 任务的首选。

  • 原生体验

    Codex 原生 Agent

    希望保留 Codex 原生 Agent 体验时的选择。

关于「角色」

角色是预设的 Agent / 模型 / 思考档位组合，不是额外的模型；预设不会自动把任务转交给另一个角色，请按任务手动选择。模型名与供应商权限随你的账号变化。

第 07 章 · 边界与排障

知道边界，才用得安心

  • 电脑休眠、断网会影响连接——保持电脑开机、联网。
  • Agent 使用真实文件和电脑权限。pi 不会每条工具调用都问你：不要把自然语言里的“确认”当成系统级权限隔离。删除、提交、部署等操作要明确授权；重要工作先备份、纳入版本管理。
  • 并行多个 Agent 时使用不同 worktree，避免它们改同一个工作区。
  • 模型授权与 API 费用分别由各供应商决定。

出问题先看这里

连接超时检查两端 Tailscale 是否在线、ACL 规则、Host 里的 IP 是否写对。
拒绝连接确认 Paseo 正在运行、监听地址与端口（6767）配置正确。
模型不可用先在终端验证对应 CLI 与登录状态，再检查 Paseo 的 provider 配置。
改动没生效daemon 重启才会加载新 listen；注意重启会中断正在运行的任务。
