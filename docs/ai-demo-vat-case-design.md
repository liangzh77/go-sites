# /ai-demo/vat-reconciliation/ 案例页设计说明

## 一、整体信息架构

沿用 case-page 骨架：`.case-wrap` > `.case-intro`（标题「AI 帮会计对增值税账」+ 一句话副标 + `.context` 元信息条：英国 / 46 人所 / 4 天试点 / VAT 对账）> `.case-workspace`（cases.js 三步 Tab）> `.case-end`。全文用「对账像对快递单」式白话，不用「销项/进项」以外的术语，必要术语首次出现加 `<dfn>` 浅橙虚线下划线。

## 二、三步内容层级

**第 1 步「算税和对账不是一回事」**（`.step-body` 内自上而下）
1. 一段 3 行白话：算税=算出该交多少；对账=核对算出来的数和实际凭证对不对得上。
2. `.case-card` 包裹 `.case-table` 三列「事项 / 金额 / 含税额」：销售收款 £1,200→£200、进货 £600→£100、应缴行加粗橙字 £100。
3. 差异追查小卡（新类 `.vat-diff`）：浅橙底（橙强调色 8% 透明度）、左侧 3px 橙条、14px 圆角，与 `.case-card` 白底拉开层级。标题「申报写了 £120，差 −£20 去哪查？」，下接 `.todos` 三条 `.todo`：漏记进项发票 / 税率或分类错 / 把含税价当净额。
4. 卡右上角胶囊标签（`.vat-demo-tag`）：橙描边白底「教学示例，非真实客户数据」，同时在表下方再出一行 `.case-note` 重复一次——两处标注，截图传播时仍有出处。

**第 2 步「四天试点做了什么」**
四张 `.case-card` 横向日程卡（新增 `.vat-day`），每卡顶部一行徽标行：`DAY 1–4` 橙实心胶囊 + 角色灰字（谁在做），卡内标题=当天产出，正文两行以内：
- D1 会计+AI｜盘点 17 类底稿，按频率/耗时/难度打分，选中 VAT
- D2 工程｜表格入库，协调助手分派核对任务
- D3 工程+会计｜接账务 API 与可检索税法；语音访谈定「缺资料先查找、找不到转会计」
- D4 全组｜代码看板交付，历史人工对账端到端比对，结果吻合
每卡底部一行「产出：××」用橙字，扫读路径 = DAY → 产出。卡间用 `.case-steps` 纵向编号容器承载，不另造时间线组件。

**第 3 步「AI 与会计谁签字」**
1. `.case-table` 职责表两列「AI 做 / 会计做」四行：备申报草稿—复核、标出差异项—逐条确认、附追查建议—判断采纳、（空）—最终签字申报。签字行会计列用橙底加粗，一眼锁定责任归属。
2. 三条边界用 `.case-note` 连续三条，前缀改为 `.vat-boundary`（左侧灰条而非橙条，与差异卡形成「提示 vs 事实边界」的色温区分，全程不用红）：① 仅此一环节试点，非全所自动化；② 「提效」未经 50 倍量化验证；③ 视频为创作者自述，非第三方审计。末条内嵌原始视频外链（橙色带 ↗）。

## 三、响应式规则

- **375px**：表格三列字号降至 13px、单元格 padding 8px；日程卡单列堆叠，DAY 胶囊与角色同排不换行；`.vat-diff` 内 `.todos` 全宽。
- **768px**：日程卡 2×2 网格；职责表保持两列；差异卡与示例表上下排列。
- **1440px**：`.case-wrap` 维持既有最大宽度不加宽；日程卡 4 列横排，卡高对齐（flex stretch）；表格不拉伸，左对齐留白。

## 四、新增 .vat- 类（仅此 5 个）

- `.vat-diff` — 差异追查卡容器（浅橙底+橙边条）
- `.vat-demo-tag` — 「教学示例」胶囊标签
- `.vat-day` — 日程卡修饰类（DAY 徽标行+产出行样式）
- `.vat-boundary` — 边界提示的灰条变体（配合 `.case-note`）
- `.vat-dfn` — 术语 `<dfn>` 的虚线下划线（可选）

交互沿用 cases.js：三步 Tab、来源切换、复制按钮，无新增 JS；Tab 全程键盘可达（ArrowLeft/Right 切换，`aria-selected` 同步），`.vat-diff` 与表格均有 `<caption>`/标题供读屏。
