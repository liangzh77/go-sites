# 微信扫码登录接入说明（网站应用）

> 状态：**占位/待配置**。当前代码只搭好了前端入口与后端回调占位，未接入真实 AppID/AppSecret，也不会发起任何外网请求。
> 适用站点：`https://liangz77.cn`（灵感书架）。

## 1. 为什么现在还不能真正登录

微信开放平台「网站应用」（OAuth2.0，`scope=snsapi_login`）要求：

1. 主体为**企业（个体工商户）**，需营业执照；
2. 完成开发者资质认证（300 元）；
3. 域名 `liangz77.cn` **已 ICP 备案**，且符合官网规范；
4. 审核通过后拿到 **AppID / AppSecret**，并在「授权回调域」里配置 `liangz77.cn`（只能配 1 个域名、每月最多改 5 次）。

在上述条件满足前，不要用个人主体抢注微信开放平台账号（主体变更较麻烦）。

## 2. 已完成的占位

| 位置 | 内容 |
| --- | --- |
| `/login/`（`login/index.html`） | 扫码登录页。读取 `window.SITE_CONFIG.wechatLogin.appId`，**为空时显示占位说明**；配置后自动加载微信 `wxLogin.js` 并渲染二维码。 |
| `site-config.example.js` / 线上 `shared/site-config.js` | `wechatLogin.appId`（公开）与 `redirectUri`。**AppSecret 绝不写入该文件**。 |
| `cmd/demo-server/main.go` | `GET /api/auth/wechat/callback` 占位处理器，固定返回 `501 WECHAT_NOT_IMPLEMENTED`。 |

配置示例（`shared/site-config.js`）：

```js
window.SITE_CONFIG = {
  publicOrigin: "https://liangz77.cn",
  privateArea: { password: "..." },
  wechatLogin: {
    appId: "wxxxxxxxxxxxxxxxxx",                                   // 审核通过后填写
    redirectUri: "https://liangz77.cn/api/auth/wechat/callback"
  }
};
```

## 3. 审核通过后的接入步骤

### 3.1 Caddy：把回调路径反代到 Go 服务

`/api/auth/*` 目前没有被代理。需要在 `Caddyfile` 的 `main_site_routes` 里补一段：

```caddyfile
handle /api/auth/* {
    reverse_proxy 127.0.0.1:9005 {
        header_up X-Real-IP {remote_host}
    }
}
```

### 3.2 后端：实现 code 换 openid

在 `cmd/demo-server` 中把 `handleWechatCallback` 从占位替换为真实实现，逻辑如下：

1. 校验 `state`（与前端写入 `sessionStorage` 的值比对，防 CSRF）；
2. 用 `code` 调 `https://api.weixin.qq.com/sns/oauth2/access_token` 换取 `access_token` / `openid`（必要时再调 `/sns/userinfo` 获取昵称、头像）；
3. 建立服务端会话（复用现有 `sessionSecret` 的签名 Cookie 机制，或新建用户表）；
4. `302` 回跳站内页面（如 `/`）。

`AppID` / `AppSecret` 走服务端环境变量（`WECHAT_APP_ID` / `WECHAT_APP_SECRET`），写入 `/srv/apps/go-sites-demo/shared/config.env`，权限 600，**不进仓库、不进前端**。

### 3.3 前端

`/login/` 已就绪：配置了 `appId` 即渲染二维码。回调成功后由服务端设置会话 Cookie，前端可跳转首页并刷新登录态。
